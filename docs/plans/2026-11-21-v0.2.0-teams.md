# v0.2.0: sign-in, roles, admin API, limits and telemetry

The plan that brings airlock level with transponder v0.3.0 on the shared contract. v0.1.0 shipped the gateway core and the store (plans 1 and 2 of the v0.1.0 design). The other two v0.1.0 plans, the admin API and OIDC with limits and metrics, were never built. This plan builds what the contract needs from them, in one branch and one pull request.

**Goal:** a team can run airlock with its OIDC provider, give people `admin`, `member` or `viewer` access and per-tool permissions through `/admin/v1/`, run several replicas on one Postgres that pick up every change within 2 seconds, cap callers with the shared profiles (`requests` and `tools.calls`), and watch it with Prometheus and OTLP traces.

**Tracking:** #68, with one sub-issue per task (#69 to #79). Pull request: #62.

**Spec:** [docs/design.md](../design.md) sections Authentication, Authorization, Admin API, Rate limits, Running several replicas and Operations, and the shared rules in [CONTRACT.md](https://github.com/raven-clown/mothership/blob/main/CONTRACT.md) and [docs/scale.md](https://github.com/raven-clown/mothership/blob/main/docs/scale.md). Where design.md and the contract disagree (rate limit rules versus profiles, metric names), the contract wins and design.md is fixed in Task 11.

**Reference:** transponder v0.3.0 solved the same pieces. `internal/auth/oidc.go` and `jwks.go` (token checks and the JWKS cache), `internal/limits` (rates with GCRA, profiles), `internal/admin` (handlers, pages, `If-Match`, the spec test) and `internal/telemetry` (Prometheus registry, tracer, OTLP/HTTP exporter) are ported where they fit, with airlock's types.

## What is in, what moves to v0.3.0

In v0.2.0:

1. OIDC sign-in with a cached JWKS, the protected resource metadata document, and the three roles from `role_bindings`. Per-tool permissions are the existing rules.
2. The admin API under `/admin/v1/` with `api/openapi.yaml`: status, servers, tools, rules, API keys, role bindings, settings, profiles, profile bindings, me, check and audit. Lists, errors, `If-Match`, `managed_by_file` and an audit record for every write in the same transaction. First start prints a bootstrap admin key.
3. Postgres replicas: already polling the revision every 2 seconds since v0.1.0. This plan adds an instant local reload after an admin write, the reload state in `/status`, and a two-replica test on Postgres.
4. Limits from shared profiles: `requests` (rate, concurrency) on every HTTP request and `tools.calls` (rate, concurrency) on every tool call, bound by key, user, group, the profile claim and `default_profile`, plus `org_profile`. 429 `rate_limited` and `concurrency_limited`, 503 `overloaded` past `limits.max_inflight`, `RateLimit-Policy` and `RateLimit` headers.
5. `/metrics` with the shared names and airlock's own series, and OTLP/HTTP traces with a span per request, per tool call and per backend call.

Moved to v0.3.0, each as an issue on the v0.3.0 milestone:

- Counters shared across replicas (the `sql` and `valkey` limit stores). v0.2.0 counts in each replica, so a limit can be passed by up to its rate times the number of replicas. The docs say so.
- CloudEvents usage events (`dev.mothership.airlock.tool.called.v1`) with an outbox, and the `roles` flag (`gateway`, `admin`, `worker`).
- Encrypted secret literals (#24). Until then the admin API accepts only `${VAR}` references in server `env` and `headers`, so no secret value is ever stored by the API.
- Personal API keys (`/me/api-keys`), `/usage`, `/sessions`, `/export`, `POST /servers/test`, `POST /servers/{name}/restart`, project bindings, `GET /limits/{subject}`, `profiles_file`, and daily and monthly quotas (402 `quota_exceeded`).
- The CLI commands that call the admin API (`check`, `tools`) and `validate`.

## Global constraints

- Everything from the earlier plans still holds: TDD, table tests, no network in unit tests, no bare `time.Sleep`, both store engines through `storetest`, coverage at 80% or more.
- No SQL read on the request path. Keys, the JWKS, roles, profiles and rules come from the snapshot; counters from the in-memory store. Admin requests may read SQL.
- The new migration only adds tables and columns with defaults (expand). A test fails on a migration after 0001 that drops or renames without a `-- contract:` line.
- No new dependency except `github.com/go-jose/go-jose/v4`, the one transponder uses for JWTs. Metrics and OTLP are hand-written as in transponder, and the admin handlers are hand-written and checked against `api/openapi.yaml` by a test instead of generated, so `oapi-codegen` is not added.
- A tool call refused by `tools.calls` is a tool result with `isError: true`, as design.md says, not an HTTP 429: the HTTP request carries a JSON-RPC message, and an MCP client treats a 429 there as a broken transport while a model can read a tool error. Its text starts with the contract's code (`rate_limited` or `concurrency_limited`) and gives the retry time. The `requests` limit on the HTTP request itself answers 429 as the contract says.
- No label on a metric and no span attribute carries a subject, a key, a token or tool arguments. Tool and server labels are only names in the catalog, anything else is `other`.

## Review focus

1. **A token from another issuer, or signed with a key the issuer does not have.** Rejected without fetching anything for the first, at most one JWKS fetch per 10 seconds for the second. Task 4.
2. **An admin write that would leave a config that does not load.** It is refused with 400 naming the field, and nothing is written. Task 9.
3. **Two replicas on one Postgres.** A rule created through the admin API of one is enforced by the other within 2 seconds. Task 10.
4. **A member reading `/audit`.** Only their own records come back, whatever filter they send. Task 9.
5. **A caller over `requests` or `tools.calls`.** 429 with `Retry-After` and the headers for the first; an error tool result, audit outcome `rate_limited` and `airlock_limited_total{reason="rate_limited"}` for the second. Tasks 2 and 8.
6. **The bootstrap key.** Printed once to stderr on a store with no role bindings, never into the JSON log, never again on the next start. Task 9.

### Task 9: The admin API (#77)

Closes #19, #23. Part of #20, #21, #22, #26.

**Files:** create `api/openapi.yaml`, `api/api.go` (embeds it), `internal/admin/*.go` and tests, `cmd/airlock/bootstrap.go`, `cmd/airlock/keys.go`.

**Endpoints** (all under `/admin/v1`): `GET /openapi.yaml`, `GET /status`, `GET /tools`, `GET POST /servers`, `GET PATCH DELETE /servers/{name}`, the same five for `/rules`, `/role-bindings`, `/profiles` and `/profile-bindings`, `GET POST /api-keys`, `GET PATCH DELETE /api-keys/{name}`, `POST /api-keys/{name}/revoke`, `GET PATCH /settings`, `GET /me`, `GET /me/tools`, `POST /check`, `GET /audit`.

**Rules:**
- Roles: `GET /me`, `GET /me/tools` and `GET /audit` need `member`; the other reads and `POST /check` need `viewer`; every write needs `admin`. `/audit` for a member is limited to their own subject.

- Every write is checked with `config.Validate` and the limits and OIDC checks on the whole config as it would be, then stored with its audit record (`kind: admin`, action, resource, route, caller, request id; no secret values), then reloaded on this instance before the answer.
- Server `env`, `auth.headers` and `auth.discovery_headers` values must be `${VAR}` references and are returned as `{"ref": "${VAR}"}`, or `{"set": true}` for a literal from the file. A stdio server's command must match `stdio.allowed_commands` when the list is set.
- `POST /api-keys` returns the key once. `GET` never returns the hash.
- First start: with no role bindings in the store, airlock creates the API key `bootstrap` and the bindings `bootstrap-admin` (`key:bootstrap` to `admin`) and `everyone` (`*` to `member`), and prints the key once to stderr. `airlock bootstrap-key` issues a new one offline. `airlock keys new --name n [--group g]` prints a key and its YAML entry.

### Changes made while building

- Headers whose name does not look secret, such as `X-Project`, may hold a plain value through the API. Values that must be references have to be exactly one `${VAR}`, or an auth scheme word and one `${VAR}` for a header, so a literal cannot ride along with a reference.
- With `stdio.allowed_commands` set, the API also refuses `..` in the command, `dir`, and env variables that change which code a program loads. The list still does not limit arguments; that is on the v0.3.0 list.
- `ops_listen_addr`, from the contract's scale rules, moves `/metrics`, `/healthz` and `/readyz` to their own port.
- `serve --stdio` makes no bootstrap key: its log stream is stderr, and there is no admin API to use one with.
- OIDC subjects that start with `key:` are refused, so a token cannot pass for an API key where subjects are compared.
- Fixed #59: `${VAR}` in Streamable HTTP headers was sent unresolved, which the admin API's reference rule depends on.
